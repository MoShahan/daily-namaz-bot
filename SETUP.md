# 🛠️ Daily Namaz Timings Bot – Setup Guide

This guide explains how to create your own Daily Namaz Timings Telegram bot using Python, GitHub Actions, the Telegram Bot API, and the AlAdhan Prayer Times API.

You will create a Telegram bot, configure a GitHub repository, add the required secrets, and automate daily prayer-time messages.

## 📋 Prerequisites

You will need:

- A Telegram account.
- A GitHub account.
- Basic familiarity with GitHub repositories.
- Python 3.12 or later for local testing (optional).

No paid hosting service or continuously running server is required. GitHub Actions runs the bot on a scheduled workflow.

## 1. Create a Telegram Bot

Telegram provides an official bot creation tool called BotFather.

1. Open Telegram.
2. Search for **@BotFather**.
3. Start a conversation.
4. Send `/newbot`.
5. Enter a display name for your bot.
6. Enter a unique username ending in `bot`.
7. BotFather will generate a bot token.

Save the token securely. You will need it when configuring GitHub Secrets.

**Important:** Never publish your bot token in your source code or commit it to GitHub.

## 2. Get Your Telegram Chat ID

The bot needs a chat ID to know where to send daily messages.

1. Open your newly created bot using its Telegram username.
2. Press Start or send it a message.
3. Open this URL in your browser, replacing `YOUR_BOT_TOKEN` with your actual token:

```text
https://api.telegram.org/botYOUR_BOT_TOKEN/getUpdates
```

4. Find the `chat` object in the response.
5. Copy the value of `id`.

This is your Telegram chat ID.

For a private chat, it is usually a numeric ID. Group chat IDs are also supported, provided the bot has permission to send messages there.

## 3. Create a GitHub Repository

Create a new GitHub repository for your bot.

You can name it something like:

`daily-namaz-bot`

Add the following project structure:

```text
daily-namaz-bot/
│
├── .github/
│   └── workflows/
│       └── daily-namaz.yml
│
├── bot.py
├── location.json
├── requirements.txt
├── README.md
└── SETUP.md
```

The main files have the following responsibilities:

| File | Responsibility |
|---|---|
| `bot.py` | Fetches prayer timings, processes Telegram commands, and sends messages. |
| `location.json` | Stores the selected location, coordinates, and last processed Telegram update ID. |
| `requirements.txt` | Lists Python dependencies. |
| `daily-namaz.yml` | Defines the GitHub Actions schedule and execution steps. |

## 4. Configure GitHub Secrets

Your bot token and chat ID should be stored as repository secrets.

1. Open your GitHub repository.
2. Navigate to **Settings**.
3. Open **Secrets and variables → Actions**.
4. Select **New repository secret**.
5. Add the following secrets:

| Secret name | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Token generated by BotFather |
| `TELEGRAM_CHAT_ID` | Your Telegram chat ID |

The Python script reads these values from environment variables.

Never hardcode these credentials in `bot.py`.

## 5. Configure the Initial Location

Create a file named `location.json`.

Example for Uppala, Kerala:

```json
{
  "city": "Uppala",
  "state": "Kerala",
  "country": "India",
  "latitude": 12.684361,
  "longitude": 74.900682,
  "last_update_id": null
}
```

Replace the city, state, country, latitude, and longitude with your preferred location.

The coordinates are used to calculate prayer timings.

The `last_update_id` field tracks Telegram updates that have already been processed, preventing old commands from being repeatedly handled.

## 6. Understand the APIs

This project uses three APIs.

### Telegram Bot API

**Purpose:** Sends daily prayer messages and receives commands from Telegram.

Documentation: https://core.telegram.org/bots/api

Important endpoints:

| Endpoint | Purpose |
|---|---|
| `sendMessage` | Sends prayer timings to your Telegram chat. |
| `getUpdates` | Retrieves incoming Telegram messages and commands. |

The bot uses Markdown formatting to make prayer names and the message heading readable.

### AlAdhan Prayer Times API

**Purpose:** Provides daily prayer timings and Hijri dates.

Documentation: https://aladhan.com/prayer-times-api

The project uses the coordinate-based endpoint:

```text
https://api.aladhan.com/v1/timings/{DD-MM-YYYY}
```

Example query parameters:

```text
latitude=12.684361
longitude=74.900682
method=1
school=0
timezonestring=Asia/Kolkata
```

Calculation settings:

| Parameter | Meaning | Current value |
|---|---|---|
| `method` | Prayer calculation method | `1` – Karachi |
| `school` | Asr calculation school | `0` – Shafi |
| `latitude` | Location latitude | Configured in `location.json` |
| `longitude` | Location longitude | Configured in `location.json` |
| `timezonestring` | Local timezone | `Asia/Kolkata` |

You can change the calculation method and Asr school through the GitHub Actions environment variables.

### Open-Meteo Geocoding API

**Purpose:** Converts a city, state, and country into geographical coordinates.

Documentation: https://open-meteo.com/en/docs/geocoding-api

Endpoint:

```text
https://geocoding-api.open-meteo.com/v1/search
```

This API does not require an API key.

When someone sends `/setcity`, the bot uses this API to resolve the requested location and retrieve its latitude and longitude.

## 7. Configure Python Dependencies

Create `requirements.txt`:

```text
requests
```

The `requests` library is used to communicate with the external APIs.

## 8. Configure GitHub Actions

Create the following file:

`.github/workflows/daily-namaz.yml`

```yaml
name: Daily Namaz Timings

on:
  schedule:
    - cron: "31 18 * * *"
  workflow_dispatch:

permissions:
  contents: write

jobs:
  send-namaz-timings:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install dependencies
        run: pip install -r requirements.txt

      - name: Process commands and send Namaz timings
        env:
          TELEGRAM_BOT_TOKEN: ${{ secrets.TELEGRAM_BOT_TOKEN }}
          TELEGRAM_CHAT_ID: ${{ secrets.TELEGRAM_CHAT_ID }}
          CALCULATION_METHOD: "1"
          ASR_SCHOOL: "0"
        run: python bot.py

      - name: Save updated location and Telegram update ID
        if: always()
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"

          git add location.json

          if ! git diff --cached --quiet; then
            git commit -m "Update Namaz bot location state"
            git push
          else
            echo "No location state changes to save."
          fi
```

### Understanding the Cron Schedule

GitHub Actions cron schedules use UTC.

The following expression:

```text
31 18 * * *
```

means 6:31 PM UTC every day, which corresponds to:

**12:01 AM IST the following day.**

The script fetches timings for the current date in the `Asia/Kolkata` timezone.

The `workflow_dispatch` option allows you to run the workflow manually from the GitHub Actions page.

## 9. Enable GitHub Actions Permissions

The workflow needs permission to commit updated location information to the repository.

The workflow already declares:

```yaml
permissions:
  contents: write
```

Also check the repository settings:

1. Open **Settings → Actions → General**.
2. Find **Workflow permissions**.
3. Enable **Read and write permissions**.
4. Save the changes.

If your repository uses branch protection rules, make sure they do not prevent the workflow from pushing commits to the target branch.

## 10. Run and Test the Bot

Once all files and secrets are configured:

1. Open your GitHub repository.
2. Navigate to **Actions**.
3. Select **Daily Namaz Timings**.
4. Click **Run workflow**.
5. Select your branch and confirm.

Check the workflow logs for errors.

If everything works, the bot should send a prayer timetable to your configured Telegram chat.

## 11. Change the Location Through Telegram

Once the bot is running, you can change its location using:

```text
/setcity City, State, Country
```

Example:

```text
/setcity Kochi, Kerala, India
```

The bot will:

1. Read the command from Telegram.
2. Verify that it came from the configured chat ID.
3. Resolve the location using Open-Meteo.
4. Validate the location against the prayer-time provider.
5. Update `location.json`.
6. Commit the updated location and Telegram update ID to GitHub.

The latest valid location command processed during a workflow run takes precedence.

**Note:** Commands are processed when the workflow runs, not instantly. The bot does not run as a continuously hosted Telegram service.

## 12. Troubleshooting

| Problem | Possible solution |
|---|---|
| Bot does not send messages | Verify the bot token, chat ID, and that the bot has permission to send messages. |
| `getUpdates` returns an empty result | Send a new message to the bot and check again. |
| Prayer timings API returns errors | Check the AlAdhan API status and workflow logs. Temporary failures are retried, but retries cannot guarantee availability. |
| Location command is rejected | Verify the city, state, and country spelling and check the geocoding result. |
| Location changes are not saved | Check GitHub Actions write permissions and branch protection rules. |
| Workflow does not run on schedule | Check that Actions are enabled and review the workflow's scheduled-run status. |

## 13. Important Limitations

- The project depends on the availability of the AlAdhan API for prayer timings. It currently has retry handling but no independent offline calculation fallback.
- Calculated prayer timings may differ from a local mosque's Azan timetable.
- The selected calculation method and Asr school affect the results.
- Telegram updates are retrieved when the workflow runs. The project is not a continuously running bot.
- GitHub Actions scheduled runs are not guaranteed to execute at the exact minute.
